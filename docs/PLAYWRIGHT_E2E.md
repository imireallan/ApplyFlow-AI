# E2E Testing Guide

## Overview

Playwright tests live in `frontend/tests/e2e/`. They validate the full user flow from landing page through authentication, file upload, and logout.

---

## Running Tests

```bash
cd frontend
TEST_MOCK=true npx playwright test
```

The `TEST_MOCK=true` env var is required. It tells the server-side session layer to accept mock auth tokens without calling the real backend API.

**Additional commands:**

```bash
npx playwright test --ui              # Interactive UI runner
npx playwright test --headed           # Browser visible during test
npx playwright test login.spec.ts      # Run single file
npx playwright test --grep "@auth"     # Run tests matching tag
npx playwright show-report html        # Open HTML test report
```

## Test Architecture

### Project Pipeline

Playwright uses 2 projects with a dependency chain:

```
[setup] ──writes storageState──> [chromium]
```

- **`setup`** — Runs `auth.setup.ts`. Creates `playwright/.auth/user.json` with an authenticated session cookie. All other tests depend on this running first.
- **`chromium`** — Runs all spec files using the `storageState` file. Each test starts with a valid `access_token` cookie.

### How Auth Works

The app uses HTTP-only cookies for sessions. The normal flow is:

1. User clicks Google Sign-In
2. Google returns an ID token → `/auth/google` on the backend
3. Backend validates it and returns a JWT access token
4. Server sets it as an `access_token` cookie
5. Every protected route (`/app/*`) calls `requireUser()` which validates the cookie against the backend

**The problem:** E2E tests run without the real backend. The server-side `requireUser()` loader would hit the backend API during SSR, get a 401, and redirect to `/login`.

**The solution (3 layers):**

### Layer 1: Cookie Injection (`auth.setup.ts`)

Instead of clicking through the login flow, the setup test directly injects a fake `access_token` cookie:

```typescript
// generates a fake JWT with sub: "test-user-123", exp: 7 days
const fakeToken = `${header}.${payload}.fakesignature`;
await context.addCookies([{
  name: "access_token",
  value: fakeToken,
  domain: "localhost",
  path: "/",
  httpOnly: true,
  sameSite: "Lax",
}]);
```

This cookie is saved to `playwright/.auth/user.json`. All tests in the `chromium` project read this file at startup, so every page load starts with the cookie set.

### Layer 2: Server-Side Test Bypass (`app/.server/sessions.ts`)

The `getUserFromRequest()` function checks `process.env.TEST_MOCK`:

```typescript
if (typeof process !== "undefined" && process.env.TEST_MOCK === "true") {
  const token = getAccessToken(request);
  if (token && decodeJwt(token)?.sub === "test-user-123") {
    return {
      id: "test-user-123",
      email: "test@example.com",
      // ... mock user profile
    };
  }
}
// Normal: calls backend /auth/me
```

When the server-side loader runs `requireUser()` → `getUserFromRequest()`, the mock token gets a valid user response without ever hitting the backend. When `TEST_MOCK` is not set, the real backend call executes as normal.

### Layer 3: Logout Test Manual Cookie Control

`logout.spec.ts` cannot use `storageState` at the config level because `storageState` reinjects cookies on every page load. After the logout action clears the cookie, the project config would put it right back, making the post-logout redirect assertion impossible.

Instead, `logout.spec.ts` injects the cookie manually via `context.addCookies()` before the first login verification, then does NOT reinject it after logout. This matches the real session lifecycle.

The unauthenticated test in `login.spec.ts` ("protected route redirects to login when unauthenticated") does the opposite — calls `context.clearCookies()` to strip auth and verify the redirect happens.

## Test Files

| File | What it tests | Auth |
|---|---|---|
| `auth.setup.ts` | Creates mock auth session | Writes session |
| `login.spec.ts` | Landing page navigation, protected route redirect | Auth + no-auth |
| `upload.spec.ts` | Upload page loads, file selection, form interaction | Auth |
| `logout.spec.ts` | Logout flow clears session → redirects to login | Manual cookie |

## File Structure

```
frontend/
  playwright.config.ts          # Project definitions, storage state path
  tests/
    e2e/
      auth.setup.ts             # Auth session creation
      login.spec.ts             # Login flow + unauthenticated tests
      upload.spec.ts            # Authenticated upload tests
      logout.spec.ts            # Logout with manual cookie control
  app/
    .server/
      sessions.ts               # Test-mode bypass in getUserFromRequest()
      logout.ts                 # Session destruction
  playwright/
    .auth/
      user.json                 # Auto-generated by setup (gitignored)
  .env.test                     # VITE_TEST_MOCK=true (for client-side env)
```

## Common Issues and Fixes

### ENOENT: no such file or directory for user.json

Run the setup project first: `npx playwright test --project=setup`. Or just run all tests — setup runs as a dependency.

### Tests redirect to /login unexpectedly

Make sure `TEST_MOCK=true` is set. Without it, the real backend API is called and rejects the fake token.

### "Invalid regular expression" error from sessions.ts

This was fixed — the regex was `/access_token(?:=([^;]*))|)$/` (unmatched parenthesis). The fix: `/access_token=([^;]*)/`. If you see this again, check for unescaped parens in `getAccessToken()`.

### Upload button stays disabled

The `UploadForm` component disables the submit button until a file is selected. Make sure `setInputFiles()` is called on the correct element (`data-testid="file-input"`). The file must have `name`, `mimeType`, and `buffer` properties.

## CI Pipeline

The GitHub Actions workflow (`.github/workflows/playwright.yml`) runs with `TEST_MOCK=true` in CI. The `reuseExistingServer` flag is disabled in CI (`process.env.CI`), so Playwright starts a fresh dev server for each run.
